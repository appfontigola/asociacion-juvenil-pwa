5. Sistema de Notificaciones Push

Arquitectura

ComponenteDescripción
SuscripciónWeb Push API con VAPID keys. Suscripción almacenada en Firestore pushSubscriptions
EnvíoVercel Serverless Function (/api/send-push) lee suscripciones y envía via web-push
RecepciónService Worker estático maneja eventos push y notificationclick
TriggerAutomático al crear un aviso nuevo

Flujo completo

  1. Usuario pulsa "Activar notificaciones" →浏览器 solicita permiso
  2. Si permiso concedido →浏览器 genera suscripción push
  3. Suscripción guardada en Firestore con userId como ID del documento
  4. Al crear aviso → frontend llama a /api/send-push
  5. Vercel function lee todas las suscripciones de Firestore
  6. Envía push a cada suscripción via VAPID
  7. Service Worker recibe evento push → muestra notificación nativa

Comportamiento por dispositivo

La suscripción está vinculada al dispositivo/navegador, no al usuario. Si un usuario activa notificaciones y luego cambia de cuenta, las notificaciones siguen llegando al dispositivo.

8. API Serverless (Vercel)

EndpointMétodoFunción
/api/send-push POST Envía notificación push a todas las suscripciones. Body: {title, body, url}. Lee suscripciones de Firestore, envía via web-push con VAPID.
/api/delete-user POST Elimina usuario de Firebase Auth y Firestore. Body: {userId}. Usa Firebase Admin SDK.

Ambas funciones incluyen headers CORS para permitir llamadas desde GitHub Pages.
